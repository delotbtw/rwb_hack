# ТЗ заказчика Capibara: «Модель маркетплейса: от корзины до выкупа»

## 0. Метаданные
- Версия 0.1, дата 2026-10-28, статус: черновик для команды. Только требования и проверки, решений нет.
- Источники и пометки: [PDF] текст кейса и шкала оценки; [SPEECH] речь эксперта; [REPO] README, handout, tasks, DDL raw, docker-compose; [DATA] пересчёт по 8 CSV (stdlib, sqlite); [HYP] гипотеза, не подтверждена.

## 1. Контекст и бизнес-цель
- Capibara: маркетплейс из Сан-Паулу, 09.2016-10.2018, от сотен до 7+ тыс. заказов в месяц, ~99,4 тыс. заказов [PDF][REPO].
- Проблема: 8 выгрузок из разных подсистем (заказы, платежи, отзывы) не согласованы; аналитики собирают отчёты заново и получают **разные цифры** [PDF].
- Цель: модель в схеме `core`, наполняемая из `raw`; ответы считаются **из модели**, а не из raw [PDF][REPO].
- Успех: одна цифра у всех; модель переживает новый вопрос; команда объясняет каждое решение [SPEECH][PDF].

## 2. Цели и не-цели
**Цели:** G1 модель core (+mart) с верной гранулой, ключами, справочниками; G2 верные ответы на 10 вопросов из модели; G3 сборка одним запуском с чистой базы + самопроверки; G4 записка, дашборд, стратегия, раздел про ИИ; G5 готовность к вбросу и защите.

**Не-цели:** N1 не менять raw и CSV [PDF]; N2 не строить BI, дашборд только описать [PDF]; N3 не оптимизировать схему под 5 известных вопросов [REPO]; N4 не обучать ML [HYP]; N5 не «чинить» грязь молча.

## 3. Ограничения и окружение [REPO]
- PostgreSQL 16 (Docker, `postgres:16-alpine`), БД `marketplace`, порт 5432, psql `hack/hack`.
- Схемы: `raw` (всё `text`), `core` (модель), `mart` (витрины, по желанию).
- Загрузка raw: `bash scripts/setup.sh [--reset]`, 550 759 строк; пустое неквотированное поле CSV становится NULL.
- Воспроизводимость: сборка модели из raw одним запуском на чистой базе, целиком [PDF][REPO].
- Данные: CC BY-NC-SA 4.0 (некоммерческое использование, источник, share-alike); ПДн нет.

## 14. Приложение
**Глоссарий:** гранула - что значит строка таблицы; unknown-member - служебная строка измерения для отсутствующего значения; SCD - историчность атрибутов; вброс - смена требований в середине; ODS/датамарт в речи эксперта = core/mart [SPEECH].

**Карта меток:** FR-01..07, 10, 12..16, 20..26, 30..33 (§5) - задачи разработки модели; NFR-01..05 (§6) - сборка и качество; Q-1..Q-5 (+Q-6..Q-10 после выдачи) (§7) - запросы и ответы; CC-01..16 (§8) - на каждый решение и тест; DQ-01..14 (§9) - автопроверки; DL-1..6 (§10) - артефакты; R-, AS- (§13).
