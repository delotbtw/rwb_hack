# Документация Capibara

Capibara обрабатывает исторические данные маркетплейса Olist и показывает аналитические показатели. Проект также включает демонстрационный поток событий, который можно воспроизвести локально.

## Запуск

Нужны Docker Desktop или Docker Engine с Docker Compose, запущенный Docker и исходные CSV в `data/`. Скачать CSV можно командой `bash scripts/download_data.sh`.

```bash
make all          # база, модель, приложение, Streamlit, брокер и Grafana
make demo-replay  # воспроизвести демонстрационные события
make help         # доступные команды с описаниями
```

Первый запуск может занять время: Docker скачивает и собирает образы, а ETL загружает данные. `make all` не удаляет существующие данные. Для работы с базой и приложением без полного окружения можно использовать `make demo`.

| Сервис | Адрес | Назначение |
| --- | --- | --- |
| Streamlit | http://localhost:8501 | Метрики и страница Live |
| Приложение и API | http://localhost:8000 | Графики и доступ к данным |
| Документация API | http://localhost:8000/docs | Интерактивное описание методов API |
| Grafana | http://localhost:3000 | Дашборды |
| Redpanda Console | http://localhost:8089 | Просмотр брокера событий |
| Airflow | http://localhost:8082 | Планирование задач; запускается отдельно через `make airflow` |

## Как устроен проект

1. Скрипты в `scripts/` скачивают и загружают исходные CSV в схему `raw` PostgreSQL.
2. `pipeline/` запускает сборку SQL-модели из файлов `sql/`: подготовку данных (`stg`), основные таблицы (`core`), витрины (`mart`) и проверки качества данных (DQ).
3. `app/` предоставляет веб-страницу, графики и API. `web/` содержит интерфейс Streamlit, который обращается к API.
4. `stream/` генерирует события и обрабатывает их через Redpanda. Форматы событий находятся в `contracts/events/`.
5. `dashboards/` содержит настройки Grafana, а `airflow/` — DAG для пакетных задач.

Другие папки: `data/` — исходные файлы, `notebooks/` — ноутбуки, `tests/` — тесты, `docker/` и `docker-compose*.yml` — конфигурация контейнеров, `make/` — дополнительные команды.

## Полезные команды

```bash
make etl          # пересобрать модель и выполнить проверки
make logs         # последние логи ETL и приложения
make ps           # состояние контейнеров основного приложения
make live         # запустить сервисы потока
make stream-stop  # остановить сервисы потока, сохранив данные
make bi           # запустить Grafana отдельно
make airflow      # запустить Airflow отдельно
make notebook     # импортировать графики из ноутбуков
make down         # остановить базу и основное приложение, сохранив данные
```

`make reset` удаляет том базы данных и собирает модель заново. Для полного демонстрационного сброса потока и модели существует `make demo-reset`; эта команда также сбрасывает данные брокера. Остановку дополнительных сервисов выполняйте их отдельными командами, например `make stream-stop`, `make bi-stop` и `make airflow-down`.

Если приложение не запускается, проверьте, что Docker работает, CSV доступны и нужные порты свободны. Логи основного приложения доступны через `make logs`. Настройки окружения описаны в `.env.example`.
