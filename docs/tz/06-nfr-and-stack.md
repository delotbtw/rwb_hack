# 06. Нефункциональные требования и стек
- **Что это:** NFR- и требования к стеку. **Входы:** окружение [REPO], DQ- (03). **Выходы:** критерии сборки и допустимости стека.
- **CSV:** все 8 (загрузка в raw). **Связано:** 03, 05, 08 (AS-07), 09 (ORG-4).

| ID | Требование | Критерий |
|---|---|---|
| NFR-01 | Воспроизводимость и идемпотентность: один запуск на чистой базе после `setup.sh --reset`; повтор даёт те же счётчики и суммы | без ошибок и ручных правок |
| NFR-02 | Единообразие: snake_case, английские имена, префиксы dim_/fact_/mart_, единые типы денег/дат/ключей | ревью |
| NFR-03 | Самопроверки в сборке (ключи, FK, row counts, суммы), падают громко | DQ-01..14 в таблице/логе |
| NFR-04 | Прозрачность: комментарии с причиной решения и ссылкой на CC-ID | у каждого CC есть пометка в коде |
| NFR-05 | Расширяемость: новая метрика/срез без перестройки фактов (атомарная гранула) | сценарии вброса (04) |

## Стек
- Baseline [REPO]: PostgreSQL 16 (Docker `postgres:16-alpine`), БД `marketplace`, порт 5432, psql `hack/hack`; схемы `raw` (всё `text`), `core`, `mart`; загрузка `bash scripts/setup.sh [--reset]`.
- Команда вправе взять другую СУБД или технологию (DuckDB, ClickHouse, dbt и т.п.), если есть объективная выгода.
- **Условия допустимости:** (1) заранее зафиксировано, для чего стек нужен дальше (одна фраза обоснования); (2) воспроизводимость одним запуском с чистой базы (NFR-01); (3) сохранены схемы raw/core/mart; (4) сохранены контрольные цифры (DQ-14).
- Риск [HYP]: проверяющие, скорее всего, ждут psql-совместимый результат (ORG-4).
